# Contextual content in tool-window title bars

`ToolWindow.ToolWindowContainerTitleBarContextContentTemplate` now accepts an Uno DataTemplate for the selected tool's title bar. `DockSite.ToolWindowsTitleBarContextContentAlignment` supports Near (before the caption) and Far (between the grip and built-in buttons); Far is the default. The implementation follows the public Actipro contextual-content reference, while retaining independent Uno APIs rather than WPF binary compatibility.

The template root belongs to the ToolWindow, not to a shared tab container. This preserves native local state when switching between tools with the same template and when the selected tool moves between docked and auto-hide containers. Containers transfer only their known contextual presenter, not arbitrary application/editor parents. Close/hide retains the context; clearing its template and unregistering release its root and data. Template data that is a UIElement is suppressed by the shared DockContextPresenter.

A title context is created lazily when selected. Data, activation, theme and alignment changes reuse its root. Metadata writeback uses ordinary Binding and the sample's explicitly retained view-model metadata. Near/far placement moves existing controls between grid columns; it does not rebuild the title or editor. Context width is constrained against the built-in button width and leaves a caption/grip region. Size changes reconcile caption limits without polling. Context input follows native child routing, activates the selected tool, and is not treated as caption dragging or double-click floating.

The sample Appearance menu exposes Explorer title controls and alignment. Four additional real-input browser scenarios exercise metadata writeback with no geometry/chrome rebuild, selected-tab and theme retention, both alignments, auto-hide/pin transfer, close/reopen retention, and clear/reset cleanup. All preceding 118 product scenarios remain, for 122, alongside 21 model suites and the 100-cycle focus test. Definition counts are not runtime pass claims: exact-head workflow artifacts determine execution.

All six libraries advance together to 0.1.0-alpha.12. Package-only consumers compile the template and alignment APIs. This increment implements the tool-title location, including the title of an auto-hide popup; tabbed MDI tabs, docked tool tabs and auto-hide rail tabs are still separate contextual locations to implement. Full native/detached windows, linked sites, size-to-content, scrollable MDI extents, complete accessibility/RTL and certified vendor pixel parity remain unfinished. Browser CI exercises real Uno Skia through software SwiftShader, not hardware-GPU throughput.

Reference: https://www.actiprosoftware.com/docs/controls/wpf/docking/docking-window-features/contextual-content . No vendor source, templates or assets are copied.
