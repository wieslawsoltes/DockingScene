# Standard MDI pointer magnetism

`DockSite.MagnetismSnapDistance` and `MagnetismGapDistance` now configure pointer move and resize snapping in its primary StandardMdiHost. The reusable host exposes the same settings for standalone consumers. Defaults are 5 and 1 logical units, respectively; setting the snap distance to zero disables the feature. Hold Ctrl during a pointer gesture to bypass it. Existing keyboard Move/Size keeps its exact eight-unit stepping and is not subject to pointer magnetism.

These names and defaults follow the public Actipro DockSite and Standard MDI documentation. The algorithm is independently implemented: same-side edges align and opposing edges retain the requested gap. Only neighbors close on the perpendicular axis are eligible. For equal-distance candidates, lower target coordinates break ties independently of enumeration order. Resize changes only the grabbed edges, keeps opposite edges fixed, rejects candidates outside minimum/maximum constraints, and leaves untouched axes alone. Queries use raw pointer-derived bounds rather than their previous snapped result, so movement escapes the snap range immediately and cannot accumulate drift.

`WindowMagnetism` is a renderer-independent Layout package class. It defensively copies and validates at most 10,000 neighbor rectangles at construction, then answers Move/Resize queries without per-query managed allocations. Nonfinite inputs, invalid edges/constraints and overflowing rectangle edges reject. Overflowing optional gap targets are ignored rather than returned as nonfinite geometry. The host builds one plan per pointer gesture from other normal windows in the same host; hidden/minimized/maximized windows, the source window and other hosts are excluded. Queries reuse that plan and the existing controls.

The preview does not mutate the manager. Pointer release uses the existing revision-checked bounds transaction and one undo entry. Escape, pointer-capture loss, unload, manager/layout changes, host resizing or magnetism-setting changes cancel the gesture and release the plan. Changing settings is presentation work, not a model revision. Ordinary activation does not re-create template roots or frame buttons.

The sample Window menu contains magnetism settings. Window > Open independent MDI hosts sample also exposes Magnetic layout, zero/default snapping, and 1/8-unit gaps. These are normal native UI actions; diagnostics remain read-only. Sixteen model specifications include 1,000 seeded constrained resizes and a warm allocation check. Seven added browser cases use actual mouse/keyboard input to check gap geometry, Ctrl/zero bypass, both resize edges, preview/commit/undo, Escape, viewport invalidation, neighbor exclusion, and retained controls. All preceding product/pixel/binding/focus checks remain required.

This increment targets Standard MDI. The existing floating docking-preview snapping is unchanged and does not yet use these two settings. Native OS/monitor snapping, keyboard magnetism, drag-guide drawing, full vendor corner-selection behavior and certified vendor pixel equivalence are not claimed. Native desktop runtime and hardware-GPU throughput are not measured by Chromium SwiftShader tests.
