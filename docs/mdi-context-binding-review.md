# Context data binding and retained highlight paint

The first integrated browser run completed 58 host scenarios with 53 passing. The caption editor accepted text but the bound model Description stayed unchanged; the dependent toggle/state cases consequently did not meet their setup. The status template also produced no usable label. An existing, unchanged pixel test found that a disabled tab-strip highlight retained its blue paint. These were failures, not successful release results.

The contextual template root is now hosted directly in an owned visual panel rather than passed as the Content of another ContentPresenter. The template's explicit DataContext remains authoritative across attachment and theme changes; the plain-content presenter remains available for non-templated data. Pair checks still surround creation, DataContext callbacks, detach and attach. The sample declares its template data type while retaining ordinary two-way Binding; it does not substitute a manual TextChanged/model mutation handler. Opt-in diagnostics record data-context types to distinguish binding from focus failures.

For zero-thickness strip highlights, the existing retained Border now collapses and clears its brush. A zero-width line is not a visible decoration and must not leave native retained paint. The original exact-pixel and no-new-measurement assertions are unchanged. All 118 product cases, 21 model suites, package consumers and the separate 100 focus cycles remain required.

Uno's public ContentPresenter implementation synchronizes Content and DataContext and performs first-load context reset; direct visual ownership avoids involving those content-template policies a second time.
